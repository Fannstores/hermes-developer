# Observability & Operations

Build systems that can explain what they are doing and failing at.

## Rules
- Use structured logs, meaningful error messages, health checks, and actionable diagnostics where appropriate.
- Distinguish expected failures, user errors, dependency failures, and internal defects.
- Never hide failures behind broad exception swallowing.
- Add safe telemetry only when it respects privacy and project constraints.
- Define recovery, rollback, and escalation paths for important operations.
